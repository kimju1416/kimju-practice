Getting Started

🚀 시작 전 준비

실습을 시작하기 전에 이것만 알면 돼요

1

클로드 챗 가입하기

  1. claude.ai 접속
  2. Sign up 클릭 → 구글 계정으로 가입하면 가장 빠름
  3. 가입 완료 후 채팅 화면이 뜨면 성공!
2

클로드 챗 기본 사용법

  1. 채팅창에 프롬프트 입력 → 엔터 또는 전송 버튼
  2. 결과가 마음에 안 들면 → 바로 "이 부분 수정해줘" 라고 이어서 대화
  3. 새로운 주제로 넘어갈 때 → 왼쪽 위 New chat 클릭
  4. 채팅창 위쪽 모델 선택 드롭다운에서 AI 모델을 바꿀 수 있음
기본값인 Claude Sonnet 5면 이 가이드의 실습 대부분에 충분해요. 복잡한 로직의 웹앱이 자꾸 어긋나면 더 똑똑한 Claude Opus로 바꿔서 다시 요청해보고, 간단한 질문엔 가장 빠른 Claude Haiku를 써보세요.
3

파일 첨부하는 법

  1. 채팅창 왼쪽 ＋ 버튼 클릭 → 파일 업로드 선택
  2. PDF, 이미지(JPG, PNG) 등 파일 선택
  3. 프롬프트와 함께 전송하면 클로드가 파일 내용을 읽고 반영!
한글 파일(.hwp)은 읽지 못해요. PDF로 변환해서 첨부하세요.
4

결과 확인하고 저장하는 법

  1. 웹페이지를 요청하면 오른쪽 아티팩트(Artifacts) 패널에 결과가 미리보기로 바로 떠요
  2. 아티팩트 패널의 다운로드 버튼 클릭 → index.html로 저장 (메모장 필요 없음!)
  3. 저장된 파일을 더블클릭하면 브라우저에서 바로 열림!
  4. 다운로드 버튼이 없이 코드로만 보여줬다면 → 복사 버튼 클릭 → 메모장에 붙여넣기
  5. 다른 이름으로 저장 → 파일 이름 index.html, 파일 형식은 모든 파일로 변경 후 저장
GAS 웹앱(Level 2)은 파일 저장이 필요 없어요. Apps Script에 바로 붙여넣기!

2시간 완성 코스 — 학급 랜덤 뽑기 앱

가입부터 배포까지, "학급 랜덤 뽑기 앱" 하나를 실제로 처음부터 끝까지 만들어보는 연수용 타임라인이에요

⏱️ 아래 시간은 참고용이에요. 반 진행 속도, 참여자 숙련도에 맞춰 자유롭게 늘리고 줄이세요. 실습 중간에 질문이 많이 나오는 단계는 시간을 더 써도 괜찮아요. 중요한 건 시간을 맞추는 게 아니라 한 단계씩 직접 눌러보고 결과를 확인하는 것이에요.

준비

클로드 챗 준비하기

이 단계는 앞의 "시작 전 준비" 섹션과 겹치는 내용이라 여기서는 핵심만 짚어요. 아직 안 읽어봤다면 먼저 그 섹션을 훑고 오세요.

  1. claude.ai 접속 → 구글 계정으로 가입/로그인
  2. 화면 구성 확인 — 왼쪽 위 New chat, 가운데 채팅창, 채팅창 위쪽 모델 선택 드롭다운
  3. 모델은 고민 말고 기본값인 Claude Sonnet 5 그대로 사용 (이 실습엔 충분해요)

  • 화면이 영어로 나올 때: 우측 하단이나 설정에서 언어를 한국어로 변경 (기능은 동일하니 그냥 진행해도 무방)

뼈대 버전

최소 기능만 있는 뼈대 버전 만들기

처음부터 화려하게 만들지 않아요. 이름 입력 + 뽑기 버튼 + 결과 표시, 딱 이 세 가지만 있는 뼈대 버전을 먼저 만듭니다.

💬 이렇게 말해보세요 (1차 프롬프트)
학급 랜덤 뽑기 웹앱을 하나의 HTML 파일로 만들어줘. 학생 이름을 한 줄에 하나씩 입력하는 칸을 만들고, 아래에 "뽑기" 버튼을 하나 넣어줘. 버튼을 누르면 입력한 이름 중 하나를 무작위로 골라서 화면 가운데 크게 보여줘. 지금은 이 기능만 있으면 돼. 복잡한 기능은 다음에 하나씩 추가할 거야.
예상 결과 화면 — 채팅 오른쪽(또는 모바일에서는 별도 창)에 미리보기(아티팩트) 창이 뜨고, 위쪽에 텍스트영역(학생 이름 입력 칸)과 회색 "뽑기" 버튼, 그 아래 빈 결과 영역이 보여요. 이름을 입력하고 뽑기를 누르면 결과 영역에 학생 이름 하나가 크게 나타나면 성공이에요.
  1. 프롬프트를 복사해서 채팅창에 붙여넣고 전송
  2. 클로드가 코드를 만드는 동안 오른쪽 미리보기 창이 뜨는지 확인
  3. 미리보기 창에 가상 학생 이름 3~4명을 한 줄씩 입력해보기 (예: 김하늘, 이도윤, 박서연)
  4. "뽑기" 버튼을 눌러 결과가 잘 나오는지 확인

⚠️ 이 단계에서 막히면

  • 코드가 실행 안 될 때: 미리보기 창 안에서 흰 화면만 보이면, 채팅 하단에 에러 메시지가 있는지 확인하고 "오류가 나는데 고쳐줘"라고 이어서 요청
  • 미리보기 창이 아예 안 뜰 때: 창이 좁은 노트북/모바일 화면이면 채팅 상단이나 메시지 옆의 미리보기 아이콘을 눌러야 따로 열려요. 코드가 너무 길어 중간에 끊겼다면 "이어서 계속 만들어줘"라고 요청
  • 그래도 안 되면 새 채팅을 열고 프롬프트를 다시 붙여넣어보기

기능 추가 1차

기능 하나씩 추가하기 — 모둠 나누기 · 자동 제외 · 리셋

뼈대가 완성됐으면, 이제 기능을 하나씩 순서대로 요청해요. "모둠 나누기도 되고 자동 제외도 되고 리셋도 되게 해줘"처럼 한 번에 다 몰아서 요청하면 클로드가 여러 요구사항을 동시에 처리하다가 일부를 빠뜨리거나 서로 충돌하는 코드를 만들기 쉬워요. 기능 하나 → 확인 → 다음 기능 순서로 가면 중간에 무엇이 문제인지 바로 알 수 있어서 훨씬 안정적이에요.

변형 프롬프트 예시 (순서대로 하나씩 요청)
💬 1) 모둠 나누기
지금 만든 학급 뽑기 앱에 모둠 나누기 기능을 추가해줘. 2~6모둠 중에서 모둠 수를 고를 수 있게 하고, 입력한 학생 전체를 고른 모둠 수만큼 자동으로 골고루 나눠서 모둠별로 화면에 표시해줘.
💬 2) 뽑힌 학생 자동 제외
뽑기 버튼을 누르면 이미 뽑힌 학생은 다음 뽑기 후보에서 자동으로 빠지게 해줘. 그리고 화면에 아직 안 뽑힌 학생이 몇 명 남았는지도 보여줘.
💬 3) 전체 초기화 버튼
전체 초기화 버튼을 화면 오른쪽 위에 눈에 잘 띄게 넣어줘. 이 버튼을 누르면 지금까지 뽑힌 기록이 다 지워지고 처음 명단을 다시 입력하기 전 상태로 돌아가게 해줘.
  1. 1번 프롬프트를 보내고 모둠이 잘 나뉘는지 확인
  2. 문제 없으면 2번 프롬프트로 이어서 대화 (새 채팅 아님, 같은 대화 이어서!)
  3. 2번까지 확인되면 3번 프롬프트로 이어서 대화
  4. 세 기능이 서로 잘 어울리는지(모둠 나누기 후에도 리셋이 되는지 등) 마지막에 한 번 더 테스트
45~65분
재미 요소

재미 요소 더하기 — 애니메이션 · 효과음 · 기록 유지

기능이 안정되면, 이제 학생들이 좋아할 만한 재미 요소를 더해요. 아래는 기본 프롬프트 하나와, 실제 수업/행사 상황별로 바꿔 쓸 수 있는 시나리오별 변형 예시예요.

💬 기본 — 애니메이션 · 효과음 · 기록 유지
뽑기 버튼을 누르면 이름이 빠르게 돌아가다가 하나로 딱 멈추는 룰렛 애니메이션을 넣어줘. 뽑기 버튼을 누를 때 짧은 효과음도 나게 해줘. 그리고 페이지를 새로고침하거나 닫았다 열어도 지금까지 뽑은 결과와 명단이 그대로 유지되게 해줘.
시나리오별 변형 프롬프트 예시
💬 체육대회 모둠 대항전용
이 앱을 체육대회 모둠 대항전에서 쓸 거야. 뽑기 버튼을 누르면 화려한 색종이(컨페티) 효과와 함께 결과가 나오게 해줘. 배경도 더 역동적이고 응원하는 느낌으로 꾸며줘.
💬 초등 저학년용
이 앱을 초등학교 저학년 학생들이 볼 거야. 글씨를 훨씬 크게 키우고, 색깔을 더 알록달록하게, 화면 전체가 밝고 재미있어 보이게 바꿔줘.
💬 중등 발표 순서 정하기용
뽑기 결과와는 별개로, 전체 학생의 발표 순서를 미리 랜덤으로 섞어서 번호가 매겨진 리스트 형태로도 화면에 보여줘.

⚠️ 이 단계에서 막히면

  • 애니메이션이 너무 빠르거나 멈춰버릴 때: "애니메이션 속도를 절반으로 줄여줘" 또는 "애니메이션이 멈추는 버그가 있어, 고쳐줘"라고 구체적으로 요청
  • 효과음이 안 들릴 때: 브라우저가 자동재생을 막는 경우가 많아요. 버튼을 한 번 누른 뒤부터 소리가 나는지 확인하고, 안 되면 "브라우저 자동재생 제한 때문에 소리가 안 나는 것 같아, 방법을 알려줘"라고 물어보기
  • 새로고침하면 명단이 사라질 때: "localStorage로 저장이 잘 되고 있는지 확인해줘"라고 요청하면 클로드가 코드를 점검해줘요
65~95분
디자인 다듬기

디자인 다듬기 — "예쁘게"가 아니라 "화면 요소 이름"으로 말하기

이제 기능은 다 됐으니 디자인을 다듬을 차례예요. 이때 "예쁘게 해줘" 대신, 아래에서 볼 UI 요소 이름 사전에 나오는 화면 요소 이름을 그대로 사용해서 요청하면 훨씬 정확한 결과가 나와요.

💬 화면 요소 이름으로 구체적으로 요청하기
결과 화면을 카드형으로 정리해줘. "뽑기"와 "모둠 나누기" 메뉴는 탭으로 전환할 수 있게 해줘. 뽑기 결과가 나오면 화면 위쪽에 토스트 알림도 잠깐 떴다가 사라지게 해줘.

아래는 디자인 잘 뽑는 법 섹션에서 소개한 방법 중, 이 실습에 특히 잘 맞는 두 가지예요.

💬 우리 학교 색상 활용하기
우리 학교 대표 색상이 남색(#1B3A5C)이야. 이 색상을 메인 컬러로 쓰고, 포인트는 하늘색으로 해줘.
스크린샷을 첨부하는 방법도 그대로 통해요 — 마음에 드는 화면을 캡처해서 "첨부한 스크린샷과 같은 스타일로 바꿔줘"라고 요청하면 됩니다. 자세한 방법은 디자인 잘 뽑는 법 섹션의 "스크린샷 첨부하기"를 참고하세요.
95~110분
저장하기

완성한 코드 저장하기

완성됐으면 파일로 저장해서 내 컴퓨터에 보관해요. 방법은 앞의 "시작 전 준비 → 코드 저장하는 법"과 똑같아요.

  1. 미리보기 창의 다운로드 버튼(↓) 클릭
  2. 파일 이름을 index.html로 저장
  3. 저장된 파일을 더블클릭해서 브라우저로 열어보고, 지금까지 만든 기능이 다 잘 되는지 마지막으로 한 번 점검

배포(선택)

배포해서 학생·동료와 공유하기

Design Rules

만들기 전에, 이것만은

쓰는 사람이 학생이라면 화면 설계의 기준이 달라집니다

1

한 화면에 한 과제

  1. 버튼은 손가락 하나로 누를 만큼 크게
  2. 한 화면의 선택지는 4~6개를 넘기지 않기
  3. 설명 문장은 짧게, 낱말과 그림을 함께
프롬프트에 "버튼과 글자를 아주 크게" 한 줄만 넣어도 결과가 확 달라져요.
2

보고, 듣게

  1. 중요한 건 그림·색·소리로 함께 알리기
  2. 음성 읽기는 speechSynthesis 한 줄이면 붙어요
  3. 눌렀다는 걸 색이나 크기 변화로 바로 보여주기
프롬프트에 "누르면 한국어 음성으로 읽어줘(speechSynthesis)" 라고 적으면 됩니다.
3

이름 대신 번호

  1. 학생은 번호·이니셜로만 구분하기
  2. 행동·관찰 기록일수록 더 엄격하게
  3. 클로드에게 줄 프롬프트에도 실제 정보 넣지 않기
기능은 그대로인데 위험만 사라집니다. 처음 만들 때부터 이렇게 설계하세요.
4

혼자 말고, 같이

  1. 누가 볼지 먼저 정하기 — 교사만? 실무사도? 학부모도?
  2. 보기만 할 사람과 쓸 사람을 나누기
  3. 배포할 때 접근 권한을 학교 계정으로 제한
통합학급 교사와 실무사가 함께 보면, 같은 학생을 보는 눈이 맞춰집니다.

💬 이 사전, 실전에서는 이렇게 써먹어요

"이 페이지에 사이드바랑 배지 좀 넣어줘"
"검색 결과가 없을 때 빈 상태 화면을 보여주고, 저장하면 토스트 알림이 뜨게 해줘"
"메뉴를 탭으로 나누고, 각 탭 안에 카드 형태로 정리해줘"
AI에게 요청할 때는 "예쁘게 만들어줘"보다 "카드, 토글, 드롭다운, 모달을 넣어줘"라고 말하면 훨씬 정확해져요.
이렇게 하지 마세요
"예쁘게 만들어줘"
"깔끔한 디자인으로 해줘"
"모던하게 만들어줘"
너무 모호해서 클로드가 매번 다른 결과를 만들어요. "예쁜"의 기준이 사람마다 다르니까요.
이렇게 해보세요
"토스 앱처럼 만들어줘"
"배경 흰색, 포인트 컬러 파란색으로 해줘"
"둥근 카드형 레이아웃으로 만들어줘"
구체적일수록 원하는 결과에 가까워져요. 레퍼런스를 주면 클로드가 그 스타일을 따라가요.
1

참고 사이트 이름 알려주기

유명한 서비스 이름을 말하면 클로드가 그 스타일을 알고 있어요.

💬 아래에서 서비스를 골라보세요
토스(toss) 스타일로 디자인 바꿔줘. 흰 배경에 카드형 UI, 파란색 포인트로.
토스 당근마켓 네이버 카카오 애플 노션 인스타그램 배민

서비스를 클릭하면 프롬프트가 바뀌어요. 복사해서 바로 쓰세요!

2

스크린샷 첨부하기

마음에 드는 웹사이트나 앱 화면을 캡처해서 첨부하면 그대로 따라 만들어줘요.

💬 예시 프롬프트
첨부한 스크린샷과 같은 스타일로 디자인을 바꿔줘. 색상, 레이아웃, 글꼴 느낌을 최대한 비슷하게 해줘.
스크린샷을 구하는 법: 마음에 드는 사이트에서 전체화면 캡처하거나, 아래 디자인 갤러리에서 찾아보세요.
3

색상/레이아웃 직접 지정하기

원하는 색상, 배치, 분위기를 구체적으로 말해주세요.

💬 예시 프롬프트 — 색상 지정
배경은 흰색, 포인트 컬러는 초록색(#10B981)으로 바꿔줘. 버튼은 둥글게, 카드에 그림자를 넣어줘.
💬 예시 프롬프트 — 분위기 지정
따뜻한 느낌으로 바꿔줘. 베이지 배경에 갈색 글씨, 부드러운 둥근 모서리로.
💬 예시 프롬프트 — 다크 모드
다크 모드로 바꿔줘. 어두운 배경에 밝은 글씨, 네온 초록색 포인트로.
4

한 번에 다 말하지 말고, 나눠서 요청하기

처음엔 기능만 만들고, 다음 대화에서 디자인을 수정하는 게 훨씬 좋아요.

1차
"학급 투표 웹앱 만들어줘" → 기능 완성
2차
"색상을 파란색 계열로 바꿔줘" → 색상 변경
3차
"글꼴을 더 크게, 버튼을 둥글게 해줘" → 세부 조정
4차
"휴대폰에서 보기 좋게 해줘" → 모바일 최적화
한 번에 "기능 + 디자인 + 모바일 대응"을 다 요청하면 클로드가 혼란스러워해요. 나눠서 대화하듯이 요청하는 게 비결!
5

6

컬러 팔레트 사이트에서 색 조합 가져오기

색 감각이 없어도 괜찮아요. 전문가들이 만들어 둔 색 조합을 가져다 쓰면 됩니다.

💬 예시 프롬프트
이 색상 조합으로 디자인을 바꿔줘: 메인 #264653, 서브 #2A9D8F, 강조 #E9C46A, 포인트 #F4A261, 경고 #E76F51

7

디자인 스타일 키워드로 말하기

디자인 세계에는 이름이 붙은 스타일들이 있어요. 이름만 말하면 클로드가 알아서 적용해요.

글래스모피즘
반투명 유리 느낌. 배경이 비치는 카드
"글래스모피즘 스타일로 바꿔줘"
뉴모피즘
부드러운 그림자로 볼록/오목 효과
"뉴모피즘 스타일로 바꿔줘"
미니멀리즘
여백 많고 요소 최소화. 깔끔함의 극치
"미니멀하게 바꿔줘"
레트로/빈티지
옛날 느낌의 색감과 텍스처
"레트로 감성으로 바꿔줘"
네온/사이버펑크
어두운 배경에 빛나는 네온 컬러
"다크 배경에 네온 스타일로 바꿔줘"
벤토 그리드
다양한 크기의 카드가 도시락처럼 배치
"벤토 박스 레이아웃으로 바꿔줘"
8

누가 쓸 건지 알려주기

사용자가 누군지 말해주면 클로드가 그에 맞는 디자인을 잡아줘요.

💬 예시 프롬프트 — 학생용
이걸 중학생들이 쓸 거야. 10대가 좋아할 만한 활기차고 재미있는 디자인으로 바꿔줘.
💬 예시 프롬프트 — 학부모용
이걸 학부모님들이 쓸 거야. 신뢰감 있고 차분한 디자인으로 바꿔줘. 글씨도 좀 크게.
💬 예시 프롬프트 — 선생님용
이걸 선생님들이 업무용으로 쓸 거야. 정보가 한눈에 보이는 대시보드 스타일로 바꿔줘.
9

여러 시안을 받고 고르기

어떤 디자인이 좋을지 모르겠으면, 여러 개를 만들어달라고 하세요.

💬 예시 프롬프트
이 페이지를 3가지 다른 디자인 스타일로 만들어줘. A안: 밝고 따뜻한 느낌 B안: 어둡고 세련된 느낌 C안: 컬러풀하고 활기찬 느낌 각각 따로 코드를 줘. 내가 골라서 쓸게.
3가지를 다 받아본 후, 마음에 드는 걸 골라서 "B안으로 가자, 근데 버튼 색만 초록으로 바꿔줘" 이런 식으로 이어가면 돼요.
10

💬 예시 프롬프트
우리 학교 대표 색상이 남색(#1B3A5C)이야. 이 색상을 메인 컬러로 쓰고, 포인트는 하늘색으로 해줘. 상단에 학교 이름 "OO중학교"도 넣어줘.

Glossary

용어사전

클로드에게 요청할 때 알아두면 좋은 용어들. 이 단어를 쓰면 원하는 걸 정확하게 만들 수 있어요!

반응형 Responsive
화면 크기(PC, 태블릿, 휴대폰)에 따라 레이아웃이 자동으로 조절되는 것
"휴대폰에서도 잘 보이게 반응형으로 만들어줘"
그리드 Grid
화면을 격자(바둑판)처럼 나눠서 요소를 배치하는 방법
"카드를 3열 그리드로 배치해줘"
레이아웃 Layout
페이지에서 각 요소(메뉴, 본문, 사이드바 등)를 어떻게 배치하는지의 구조
"왼쪽에 메뉴, 오른쪽에 본문인 레이아웃으로 바꿔줘"
헤더/푸터 Header / Footer
페이지 맨 위(헤더)와 맨 아래(푸터) 영역. 로고, 메뉴, 연락처 등을 넣는 곳
"상단 헤더에 로고랑 메뉴 넣어줘"
사이드바 Sidebar
페이지 왼쪽 또는 오른쪽에 고정된 세로 메뉴 영역
"왼쪽에 사이드바 메뉴 넣어줘"
히어로 섹션 Hero Section
페이지 맨 처음에 보이는 큰 배너/타이틀 영역. 첫인상을 결정하는 곳
"히어로 섹션에 큰 제목이랑 배경 이미지 넣어줘"
여백/패딩/마진 Padding / Margin
요소 안쪽 공간(패딩)과 요소 바깥쪽 공간(마진). 여백이 많으면 시원하게 보임
"카드 안쪽 여백 좀 더 넉넉하게 해줘"
가운데 정렬 Center Align
요소를 화면 가운데에 배치하는 것
"전체 내용을 가운데 정렬해줘"
고정 Fixed / Sticky
스크롤해도 화면에서 움직이지 않고 항상 그 자리에 있는 것
"상단 메뉴를 스크롤해도 고정되게 해줘"
카드 Card
둥근 모서리 박스 안에 이미지, 제목, 설명 등을 담은 UI 단위. 가장 많이 쓰이는 형태
"정보를 카드형으로 보여줘"
모달/팝업 Modal / Popup
화면 위에 뜨는 창. 뒤에 배경이 어두워지면서 가운데에 새 내용이 표시됨
"상세 정보를 팝업으로 보여줘"
탭 Tab
여러 내용을 같은 자리에서 전환해서 보여주는 버튼 묶음. 공간을 절약할 때 좋음
"일정, 준비물, 연락처를 탭으로 나눠서 보여줘"
토글 Toggle
켜고 끄는 스위치. 다크모드 전환, 옵션 켜기/끄기 등에 사용
"다크모드 토글 버튼 넣어줘"
접기/펼치기 Accordion / Collapse
제목을 클릭하면 내용이 아래로 펼쳐지고, 다시 클릭하면 접히는 것
"FAQ를 접기/펼치기 형태로 만들어줘"
드롭다운 Dropdown
클릭하면 아래로 목록이 펼쳐지는 선택 메뉴
"학년을 드롭다운으로 선택하게 해줘"
뱃지 Badge
작은 라벨 형태의 표시. "신규", "완료", "1등급" 같은 상태를 표시할 때 사용
"등급을 색깔 뱃지로 표시해줘"
네비게이션/GNB Navigation
페이지 간 이동할 수 있는 메뉴. 보통 상단이나 왼쪽에 있음
"상단에 네비게이션 메뉴 넣어줘"
햄버거 메뉴 Hamburger Menu
가로줄 3개(≡) 모양 아이콘. 누르면 메뉴가 열림. 모바일에서 주로 사용
"모바일에서는 햄버거 메뉴로 바꿔줘"
폼/입력폼 Form
이름, 이메일, 선택사항 등을 입력받는 양식 영역
"이름, 반, 번호를 입력하는 폼을 만들어줘"
테이블/표 Table
행과 열로 데이터를 정리해서 보여주는 표
"학생 기록을 표로 보여줘"
프로그레스 바 Progress Bar
진행률을 막대로 보여주는 것. 설문 진행률, 로딩 상태 등에 사용
"설문 진행률을 프로그레스 바로 보여줘"
캐러셀/슬라이더 Carousel / Slider
좌우로 넘기면서 여러 장의 이미지나 카드를 보여주는 것

배포 가이드

만든 웹앱을 세상에 공개하는 3가지 방법

HTML/CSS/JS로 만든 정적 페이지를 무료로 호스팅할 수 있어요. 단일 HTML 파일 결과물(Level 1, 그리고 Level 3의 안내문형 페이지)에 적합합니다.
  1. GitHub 접속 — github.com에 로그인합니다. (계정이 없으면 먼저 회원가입)
  2. 새 저장소 만들기 — 오른쪽 위 + 버튼 > New repository 클릭. 저장소 이름을 영어로 입력하고 (예: my-first-app), Public 선택 후 Create repository 클릭
  3. 파일 업로드 — 만들어진 저장소 페이지에서 uploading an existing file 링크 클릭. 클로드 챗에서 받은 코드를 저장한 파일(index.html 등)을 드래그 앤 드롭으로 올리기. 아래 Commit changes 버튼 클릭
  4. Pages 설정 — 저장소 상단 탭에서 Settings 클릭 > 왼쪽 메뉴에서 Pages 클릭 > Branch를 main으로 선택 > Save 클릭
  5. 배포 완료! — 1~2분 기다리면 상단에 초록색 박스로 주소가 나타납니다. https://내아이디.github.io/저장소이름 으로 접속하면 내 페이지가 보여요!
파일을 수정하고 싶으면? 저장소에서 파일을 클릭 > 연필 아이콘(Edit) > 수정 후 Commit changes. 자동으로 반영됩니다.
드래그 앤 드롭만으로 배포할 수 있어요. 가장 쉬운 방법! 단일 HTML 파일 결과물(Level 1, 그리고 Level 3의 안내문형 페이지)에 적합합니다.
  1. Netlify 접속 — netlify.com에 접속해서 Sign up 클릭. GitHub 계정으로 로그인하면 편해요
  2. 파일 준비 — 클로드 챗에서 받은 코드를 index.html 파일로 저장합니다 (파일 하나면 충분해요)
  3. 새 사이트 추가 — 위쪽 Add new project(또는 Add new site) 버튼 > Deploy manually 클릭
  4. 드래그 앤 드롭! — 화면에 나타나는 드롭 영역에 index.html 파일(또는 폴더)을 그대로 끌어다 놓으세요
  5. 배포 완료! — 몇 초 후 자동으로 랜덤 주소가 생성됩니다. (예: happy-cat-1234.netlify.app) 클릭하면 내 페이지가 바로 보여요!
주소를 바꾸고 싶으면? Project configuration(구 Site configuration) > 프로젝트 이름에서 원하는 이름으로 변경할 수 있어요. (예: my-class-app.netlify.app)
Google Apps Script 웹앱 배포 방법이에요. 스프레드시트와 연동되는 앱(Level 2, 그리고 Level 3의 GAS 앱)은 이 방법으로 배포합니다.
  1. 스프레드시트 열기 — 구글 드라이브에서 새 스프레드시트를 만듭니다
  2. Apps Script 열기 — 스프레드시트 상단 메뉴에서 확장 프로그램 > Apps Script 클릭. 새 탭에서 코드 편집기가 열립니다
  3. 코드 붙여넣기 — 클로드 챗에서 받은 코드 중 Code.gs 내용을 기본 파일에 붙여넣기. 왼쪽 파일 목록 옆 + 버튼 > HTML 선택 > 이름을 index로 입력 > 클로드가 준 HTML 코드 붙여넣기
  4. 저장 — 위쪽 디스크 아이콘 클릭하거나 Ctrl+S
  5. 배포하기 — 오른쪽 위 배포 버튼 > 새 배포 클릭
  6. 유형 선택 — 톱니바퀴 아이콘 > 웹 앱 선택
  7. 액세스 설정 — "다음 사용자로 실행"은 나, "액세스 권한이 있는 사용자"는 모든 사용자로 선택
  8. 배포 클릭! — 권한 승인 팝업이 뜨면 액세스 허용 클릭. 웹앱 URL이 나타나면 복사해서 공유하면 끝!
코드를 수정했으면? 배포 > 배포 관리 > 연필 아이콘 > 버전을 "새 버전"으로 선택 > 배포. 기존 URL은 그대로 유지됩니다.
FAQ

자주 묻는 질문

막히는 게 있으면 여기서 먼저 찾아보세요

클로드가 코드를 잘라서 보여줘요 (코드가 중간에 끊김)
클로드 답변 길이에 제한이 있어서 긴 코드는 중간에 잘릴 수 있어요. 답변이 끊기면 화면에 "계속" 버튼이 뜨는데, 그걸 누르면 이어서 작성해요. 버튼이 안 보이면 "이어서 보여줘" 또는 "나머지 코드 계속 보여줘"라고 말해도 됩니다.
코드를 저장했는데 브라우저에서 글자만 보여요
파일이 .txt로 저장됐을 가능성이 높아요. 파일 이름이 정확히 index.html 인지 확인하세요. 메모장에서 저장할 때 "파일 형식"을 "모든 파일(*.*)"로 바꿔야 해요.
코드를 복사했는데 동작하지 않아요
몇 가지 확인해보세요:
1. 코드 전체를 복사했는지 (맨 위 <!DOCTYPE html> 부터 맨 아래 </html> 까지)
2. 파일 이름이 .html로 끝나는지
3. GAS 코드인 경우, Code.gs와 index.html을 각각 따로 만들었는지
GAS 웹앱 배포 시 "권한이 필요합니다" 가 뜨는데요?
"권한 검토" → "고급" → "(프로젝트 이름)(으)로 이동" → "허용" 순서로 클릭하면 됩니다. 구글이 안전 확인을 하는 건데, 본인이 만든 코드니까 허용해도 괜찮아요.
GAS 웹앱 코드를 수정했는데 반영이 안 돼요
코드를 수정한 후에는 다시 배포해야 해요. 배포 > 배포 관리 > 연필 아이콘 > 버전을 "새 버전"으로 선택 > 배포. 기존 URL은 그대로 유지됩니다.
클로드가 만든 결과가 마음에 안 들어요
한 번에 완벽한 결과가 나오는 경우는 드물어요! 대화를 이어가면서 수정하는 게 핵심이에요.
- "이 부분 색상 바꿔줘"
- "버튼을 더 크게 해줘"
- "레이아웃을 카드형으로 바꿔줘"
이런 식으로 구체적으로 하나씩 수정 요청하세요.
같은 프롬프트인데 다른 사람과 결과가 달라요
정상이에요! AI는 매번 조금씩 다른 결과를 만들어요. 이게 오히려 장점이에요 — 같은 프롬프트로 나만의 결과물이 나오니까요. 마음에 안 들면 "다시 만들어줘"라고 하면 새로운 버전을 줍니다.
무료로 얼마나 쓸 수 있나요?
claude.ai 무료 플랜은 5시간마다 대화 15~40회 정도 사용할 수 있어요(질문 길이·복잡도에 따라 달라짐). 하루짜리 연수·실습 시간 안에는 충분한 양이에요. 한도에 걸리면 화면에 "몇 시간 후 다시 가능"이라고 안내가 뜨니, 그 시간 이후 다시 시도하면 됩니다. 매번 실습마다 새 대화를 열기보다, 같은 대화창에서 이어서 수정 요청하면 메시지를 더 아낄 수 있어요.
모델(Sonnet, Opus...)은 뭘 선택해야 하나요?
기본값인 Claude Sonnet 5로 시작하세요. 이 가이드의 Level 1~3 실습은 대부분 이걸로 충분해요. Level 4처럼 복잡한 로직이 얽힌 웹앱에서 결과가 자꾸 어긋나면 채팅창 위쪽 모델 드롭다운에서 Claude Opus로 바꿔 다시 요청해보세요. 속도가 중요한 간단한 질문엔 가장 빠른 Claude Haiku가 좋습니다.
만든 웹페이지를 학생들에게 어떻게 공유하나요?
배포 가이드를 참고해서 GitHub Pages, Netlify, 또는 GAS로 배포하면 인터넷 주소(URL)가 나와요. 이 URL을 QR코드로 만들거나, 카카오톡/클래스룸 등으로 공유하면 됩니다!
더 빠른 방법: 단일 HTML 결과물(Level 1)은 아티팩트 패널의 게시(공유) 버튼을 누르면 배포 없이도 바로 공유 링크가 만들어져요.
HTML 파일이 여러 개(CSS, JS 따로)면 어떻게 하나요?
프롬프트에 "하나의 HTML 파일로 만들어줘"라고 하면 CSS와 JS가 모두 포함된 단일 파일로 만들어줘요. 이렇게 하면 파일 하나만 관리하면 되니까 훨씬 편합니다!
